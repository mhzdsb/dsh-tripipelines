# dsh-pipeline 评审问题汇总

- 审查对象：`dsh-pipeline` v1.11.0（BUILD_TAG v102），工作区 `Merhentz_plugin/plugin`，安装副本 `~/.dsh/dsh-pipeline-v102`（两侧逐字节一致）
- 方法：三路独立只读审查（tools/gates、host/state/UI、knowledge/prompts/tests）+ 逐行代码复核 + live 探针 + 7 套 smoke 实跑 + live 路由/看板取证
- 性质：只读审查，未改动任何代码。唯一副作用：调用一次只读 `pipeline_status` 后，工作区 `.dsh/pipeline/board.json` 被重写为「stock + todo」混合态（本身就是 P0-2 的证据）
- 统计：**P0 × 4，P1 × 13，P2 × 19，P3 × 4，文档失真 × 11**

## 0. 结论

| 维度 | 评分 | 说明 |
|---|---:|---|
| 设计完整度 | 8/10 | 三级闭环、预算/里程碑/验收/知识层都有设计，不是拼凑 |
| 工程投入 | 9/10 | 4,305 行 lib、12 万字符文档、7 套 smoke（75/49/ALL/ALL/15/27/byte-equal）、release 有快照校验 |
| 作为「工具箱」 | 7/10 | 脚手架、看板、知识索引、人工 step-by-step 都好用 |
| 作为「自动产线」 | 4/10 | 四个 P0 指向同一件事：宣称的硬边界没有一条是机械强制的 |

一句话：**设计有想法、工程有手艺，但"可信"是写出来的，不是守出来的。**

## 1. P0 — 阻断「可信自动化」

### P0-1 质量门对 JS/TS 项目不设防

- 位置：`plugin/lib/gates.js:55-82`、`gates.js:124-133`、`plugin/lib/util.js:102-113`
- 现象：
  1. 执行断言只在宿主机跑 Python；任何异常（含 python 不存在、非 Python 代码）→ `{ran:false}`（gates.js:74-77），随即回退 `semanticScore`（gates.js:128-133）。
  2. `semanticScore` 只要文本里有任意一个 `{`/`function`/`return` 等结构特征就给 0.6，再按关键词覆盖率加分；两个关键词命中即达 0.7 阈值。
  3. 0.7 是**断言通过率**（gates.js:124-126）：4 条断言错 1 条也过，错 2 条反而不过。
- 影响：README 目标用户是 Node 项目，实际等价于「只要代码像代码就给过」；这是整个产品最核心的卖点。
- 修复方向：`ran:false` 必须硬失败（或明确"该语言不支持执行断言→必须人工复核"）；0.7 改为「全部断言通过」；语义分只能作为**附加**信号，不能单独过门；补 JS/TS 断言支持或明确拒绝。
- 验收：新增 smoke：`function add(a,b){return a-b}` + `add(2,3)==5` 必须 fail；非 Python 项目 + 无执行能力必须 fail。

### P0-2 单 store 跨工作区串味

- 位置：`plugin/lib/plugin.js:29-40`（进程级单 store）、`plugin/lib/store.js:162-190`（`setStateDir` 复制上一工作区 requirement_lock 到新工作区，:169-173）、`store.js:66-146`（恢复只合并不清空）、`plugin.js:109,114`（每次工具调用重新 alignTo）
- 现象：同一 daemon 进程内，A 工作区的需求锁/任务/L2 记录会进入 B 工作区；board.json 的两份 run（`run-1793200544407` 与 `run-1793210725700`）混在一起，`requirement_lock.json` 与 board 的 run_id 不一致。
- 现场证据（本机）：
  - `.dsh/pipeline/board.json` 含 `D:\Vctest\stock` 的 `k1–k4`（pending）与 4 个 `in_progress` 的 L2（knowledge-decisions / knowledge-index / research-next-path / docs-alignment），同时还有 todo-cli 的 cli-core/cli-tests。
  - 调一次只读 `pipeline_status` 就返回了这 4 个 stock L2 及其 token（25026/33976/17113/28387）。
  - `.dsh/pipeline/knowledge/` 同时存在 stock 的 19 个模块页与 Merhentz_plugin 的 index.md。
- 修复方向：store 按 `stateDir` 分实例（`Map<absStateDir, store>`），`setStateDir` 只切换不复制；`restoreFromDir` 先清空再恢复；requirement_lock 严格归属 run。
- 验收：同一进程内先后对两个不同 cwd 调用工具，B 的 board 不得出现 A 的任何 task/agent/lock。

### P0-3 三层边界只是 prompt，不是 enforcement

- 位置：`plugin.js:150-157`、`plugin.js:21`（`agentTeams` 不在 inject）、`guards.js:72-83`（`isRootCoordinator` 四种情况全 `return true`）、`guards.js:39-56`（`pipeline_decompose` 在 L1_ONLY_TOOLS）
- 现象：守卫只在 `agentTeams.membership(execution.agent)?.role === 'lead'` 时拒绝；服务取不到、归属失败、异常一律放行（catch 视为「subagent → allow」）。
- 影响：
  - L1 可直接调 `pipeline_execute_local` / `execute_batch`，绕过 L2/L3 与运行预算记账（`prompts.js:13`、`TUTORIAL.md:66` 的「guard rejects them」不成立）。
  - `pipeline_decompose` 在 L1 被 prompt 禁止（prompts.js:13）、在 L2 被 guards 拒绝（guards.js:48）→ 团队模式下**无任何合法调用者**；README:196 / TUTORIAL:54 却写它是 L2 工具。
- 修复方向：拒绝路径 fail-closed；层级在 `tools.register` 时按作用域强制（而不是查看板 membership）；`decompose` 的归属在 prompt/文档/守卫三处统一；补拒绝路径的单测。
- 验收：L1 调 execute_local 必须被拒；L2 调 decompose 必须被拒；三条规则各有断言。

### P0-4 知识层秘密安全有两个真实漏洞

- 位置：`plugin/lib/knowledge/scan.js:152` → `scan.js:283`；`plugin/lib/knowledge/recall.js:59`
- 现象：
  1. `checkpointState()` 取 `dev/project_checkpoint.md` 的 `## 0.` 前 420 字原样返回（scan.js:152），`index.md` 拼装时**不做脱敏**（scan.js:283）；全文件唯一的 `redact()` 调用在 `scan.js:249`，只覆盖 doc heads。模块页（scan.js:433）与 ledger 行（ledger.js:91-104）也是原文。
  2. `recall.js:59` `join(knowledgeDir, rel)` 不做规范化，`files:["../../../.env"]` 可把工作区 `.env` 读进上下文。
- 影响：与 `SKILL.md:19`「secret files are never read…」直接矛盾；模型在 checkpoint 里记下的 key 会被发布到「skill 让它第一个读的文件」。
- 修复方向：知识层所有写入点统一脱敏；recall 用 `realpath` 校验必须位于 knowledgeDir 之内，并拒绝 secret 扩展名；补两条负向测试（checkpoint 里放 key、`../../../.env`）。
- 验收：v98/v99 增加「inline key 不出现」「越界路径被拒」断言。

## 2. P1 — 承诺与实际不符，或会造成误判

### P1-1 冻结是装饰性的

- `plugin.js:184-196` `/pipe-stop` 设 `paused=true; status='paused'`，但 `store.js:319-322` `budgetRefusal` 首行 `if (!run || run.status !== 'active') return ''` → 暂停后预算护栏反而全部放行。`/pipe-resume` 同理。
- 修复：先判 paused，再判 active；`/pipe-stop` 的承诺要能被测试证明。

### P1-2 运行页脚永不出现

- `guards.js:27-34` 只处理 `string` 或 `{type:'text'}`；13 个 RUN_FOOTER_TOOLS 全部用 `text()`/`jsonOutput()`，render 返回**数组** → 原样返回。
- 实测：`pipeline_status.output.render({}, …)` 返回 array，`footerPresent:false`；README:77「工具结果尾部实时显示进度」不成立。
- 修复：`withRunFooter` 处理 `ContentBlock[]`；补渲染级测试。

### P1-3 验收自证，且可被 re-plan 抹掉

- `l1.js:575` 直接把 `m.state='accepted'`，没有任何「用户确实同意」的机械证据。
- `l1.js:156` 覆写 `run.milestones`：重新 plan 会抹掉「done 未验收」的里程碑，`guards.js:58-60` 的「永不被悄悄跳过」只是文案。
- 修复：accept 需要显式用户确认凭据（例如必须携带 `ask_user_question` 的答案或 `confirmedByUser:true` 并记录）；re-plan 保留未验收里程碑。

### P1-4 恒真检查与状态失真

- `gates.js:155` `jsonOk = isPlainObj({ code })` 恒真；`gates.js:141-165` `subtaskRecords.every(...)` 对空数组恒真；`gateTask` 不查行数/status，只用 semanticScore。
- `l2l3.js:396` 把 `subtask_id` 伪造成 `s.id` 再与 `s.id` 比 → id 检查恒真；真实 id 在 `l2l3.js:234-235` 被丢弃。
- `l2l3.js:350` `if (out && out.ok) done += 1` 把 `state='review'`（未过门）计为 done；批次返回的 done=N 是「已提交」不是「已验收」。
- `l2l3.js:439-443` filePath 复核仅凭 semanticScore 就把 `failedSub.state='done'`（现场 `tc-readme` failCount=1 但 state=done）。
- `l2l3.js:531/547-549` 非 JSON 回复被存成 `state:'done'`、`code:null`。
- `l2l3.js:270` `JSON.stringify(parsed.code ?? parsed)` 在 `parsed=null` 时抛异常，且位于计数之后、try 之外 → execute_local 场景子任务永远停在 in_progress（守卫不再放行）。
- 修复：每个 check 必须可证伪（去掉恒真项）；拆分 `submitted / gated / accepted` 三态；写状态前先保证数据可序列化。

### P1-5 路径按 daemon cwd 解析（项目级配置/checkpoint 永远读不到）

- `config.js:190-200` `resolve(join(devDir,'pipeline-project.json'))`；`l1.js:403-404` `resolve(join(cfg.devDir,…))`；`gates.js:47` scratch 目录；`prompts.js:29-30` `resolve(cfg.devDir)`。
- live 证据：`GET /pipeline/board` 返回 `debug.cwd=C:\Users\Merhnztz\.dsh\profiles\desktop`，而 stateDir 指向项目 `.dsh/pipeline`。
- 修复：统一走 `workspaceRoot`（`resolveWorkspaceRoot` 已有），并在 `plugin.js` 里注入/传递。

### P1-6 配置回写污染全局 + 甜点区错配

- `config.js:126-135,331` `savePersistedConfig` 把合并后的**全部键**写回全局 `~/.dsh/pipeline/config.json`：项目层覆盖值会泄漏为全局默认。
- `~/.dsh/pipeline/config.json` 的 `level1Model=deepseek-pro`，而当前会话实际是 `deepseek-flash`（refresh 后 list_agents 确认）→ 甜点区按 0.5 计算 64000，实际应为 0.25=32768，L1 上下文压力读数偏差约 1 倍。
- 修复：持久化只写用户显式修改的键；甜点区优先用会话实际模型（`resolveSessionModel`），并在 status 中显示来源。

### P1-7 默认值绑作者机器

- `config.js:37-39` 默认 `level3Endpoint=http://127.0.0.1:18200/v1`、`level3Model=qwen3.8-27b-gsq-rco-iq3-s-mtp`，而注释（config.js:24-26）与实际安装配置都是 `127.0.0.1:8080` + `qwen3.8-flash-next-iq3_xxs`。新用户开箱即指向死端口。
- `l2l3.js:508-514` 硬编码 `agentOptions:{provider:'ninfer-local'}`（作者机器专属 LLM provider 名），`l1.js:271` 硬编码 `provider:'spawn'`。
- `l2l3.js:181-183` `level3InputBudget=500` 直接 failed（500 token 对代码任务极低）。
- 修复：默认值去个人化；provider 名进配置并 selftest 校验；input budget 给合理默认并支持超限裁剪而非硬拒。

### P1-8 宿主机执行模型产出的代码

- `gates.js:55-73`：`exec(<code>)` + 对模型写的 acceptance 做 `eval()`，`execFileSync('python', …, {stdio:'ignore'})`，无沙箱、无白名单、无网络隔离。
- 影响：L3 输出（或 prompt injection 注入的验收文本）可在宿主机执行任意 Python。
- 修复：默认关闭执行断言（opt-in）；至少加超时/禁网/临时目录/受限 builtins；与 P0-1 一起改。

### P1-9 静默失败与谎报

- 17 处 best-effort 静默 catch（l1.js 94/257/263/373/449、l2l3.js 84/547、gates.js 26/48/52/74/82、guards.js 80、util.js 130/135/144/187）。
- `l1.js:373-378` drainChildren 失败被吞后仍返回 `{drained: ids}` 并把 agents 置 done。
- `l1.js:257` handoff 缺失静默成 null；`l2l3.js:84-87` L2 分解失败静默降级为按 500 token 切块。
- 修复：区分「可降级」与「失败」；降级必须写 trace + 在返回里标注。

### P1-10 看板路由：无鉴权、泄露、响应头顺序、disposer 丢失

- `board-route.js:183-194` 无鉴权/方法/来源检查，返回绝对 `stateDir`、`debug.cwd`、需求 200 字、scopeDir、错误串。
- `board-route.js:183-193` 先 `writeHead(200)` 再 `buildBoardSnapshot` → 抛错会 `ERR_HTTP_HEADERS_SENT`。

- 修复：本机 token 或仅 loopback；先构建再 writeHead；保存 disposer；GET 只读。

### P1-11 预算账目失真

- L2 分解调用不计数（l2l3.js:14-42）。

- `maxLevel2Retries` 只在配置/提示里出现（config.js:91；prompts.js:15,41），任何门/工具都不计数。
- `counters` 只存内存（store.js:33），`restoreFromDir` 不恢复 → 重启后计数器归零（现场 counters 全 0 而 tokensUsed=14526）。
- 修复：统一在 LLM 调用边界记账；filesTouched 填真实路径；counters 持久化。

### P1-12 测试与发布卫生

- `package.json:29` test 只串 5 套（v82/v89/v90/v92/skill_sync），v98/v99（15/27 全绿）没进；README:274 写「7 套」。
