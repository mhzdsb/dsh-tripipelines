# 示例 1：全栈待办应用（React + Vite + localStorage）

## 直接粘这句给 DSH

```
帮我做一个带登录和任务列表的待办应用，React + Vite，数据存 localStorage。
要求：注册/登录/退出（localStorage 存会话）、任务增删改查、按完成状态筛选、
响应式布局、至少一个组件有单元测试。
```

## 流水线会怎么跑（预期行为）

1. **需求访谈**会问 3–4 个关键问题（认证强度？要不要多用户？测试框架？样式方案？），锁定需求。
2. **拆模块**（示例，实际由 L1 生成）：
   - `auth`：注册/登录/会话管理
   - `tasks`：任务 CRUD + 状态筛选
   - `ui`：布局、组件、响应式样式
3. **L2 各自写完整文件**，`ui` 模块可能把样式片段下放 L3（单函数级）。
4. **质量门**：auth/tasks 的验收里写函数级断言语义（如 `validateEmail('a@b.c')==true`），`ui` 用关键词/结构检查。
5. **里程碑**：`MVP 可用`（三模块跑通）→ 弹窗验收 → checkpoint。

## 想省更快 / 想更稳

- 想快：说「L3 只做纯函数，样式不用 L3」。
- 想稳：说「每个模块完成后跑一次测试」。
- 别做的事：一次扔 10 个模块——按里程碑分批，L1 会控制节奏。
